# M2 Private Beta Gate

This delivery adds an explicit service entry, not a public release. Normal `npm start`, including with `GITLINEAGE_PRIVATE_BETA=1`, never installs the gate. Public Graph and canonical analysis stay unchanged. The entry is `npm run preview:private-beta`; it binds loopback. No OCI configuration is changed.

## Authorization contract

Explicit opt-in `GITLINEAGE_PRIVATE_BETA=1`, fixed `GITLINEAGE_BETA_ORIGIN` (default loopback port 8083), `GITLINEAGE_BETA_STORE` outside checkout/cache/jobs, and `GITLINEAGE_BETA_ADMINISTRATORS` JSON are required. Administrators have stable `id`, random hexadecimal `salt` (32–128 hex characters), and 128-character scrypt `passwordHash`. Generate salts with Node crypto and use `passwordHash` from `experiments/private-beta/gate.ts` in a trusted provisioning process. Supply hashes through a protected process configuration; never put a password or credential in a URL or command history. There are no shipped accounts or passwords.

Visit `/private-beta`, submit administrator identity/password in a same-origin JSON request, then open the existing Deep Search workspace. Login and all writes require exact Origin, JSON and `x-gitlineage-csrf: 1`. No cross-origin CORS permission is issued. Host is checked against configured origin; Forwarded and all X-Forwarded headers are rejected, never trusted for authentication. HTTP is allowed only on loopback; HTTPS cookies add Secure. Cookies are HttpOnly, SameSite Strict, expire after 15 minutes. Login rotates and revokes the prior session for that identity; logout revokes it even after the identity exhausts its request-frequency allowance. Sessions are not persisted and expire on restart. A still-valid stolen cookie remains a bearer credential: TLS, safe administrative devices and later stronger authentication remain operational requirements.

Unauthenticated requests cannot instantiate Preview or create tasks/budgets/GitHub requests. Unknown or foreign task IDs are unavailable. Per-identity Preview engines persist across login sessions, preserving Search → Sources → Compare binding and the existing cumulative 24-attempt/30-second/1-MiB reservation ceilings. Comparison uses the existing worker; no new algorithm or lineage rules.

## Single-instance resource contract

Defaults (only reductions allowed): two global active tasks, one per identity, 96 reserved GitHub attempts per service hour, two searches per identity per hour, 90 authorized HTTP requests/minute/identity (private UI polls at most once per second, leaving room for actions) and ten login attempts/minute globally. Search admission reserves all 24 attempts nonrefundably in durable state, even on failure or cancellation. Sources and comparison consume that same search context, never another allocation. Capabilities expose the actual engine cooldown (15 seconds by default); the existing UI disables stage submission until it expires. Known core quota below 24 rejects a new search; provider rate-limit/403/429 globally blocks further requests until the supplied reset or at least 60 seconds. No automatic credential changes, anonymous retry loop or paid API calls.

Up to 24 durable task records; expired terminal records are removed on later task admission. Task requests are capped at 4 KiB and five seconds body-read timeout. Existing per-source limits and native deadline/abort remain. CPU hard budget remains unsupported; no claim of wire-byte hard cap is made.

Durable private state holds task ownership, isolated sidecars/results, hourly reservations and provider block state. Atomic same-directory rename and mode 0600 files; directory must be owned by the service UID and have no group/other permissions (created mode 0700); shared existing directories are rejected. Store location is checked through physical paths against checkout, canonical cache and job store before creating it. Exclusive instance lock prevents accidentally running two quota authorities against one store. Graceful shutdown cancels/drains tasks and removes the lock. After an unclean shutdown, startup fails closed until an operator confirms the old process stopped and removes only the private lock. Restart then marks unfinished tasks partial with explicit restart failure, discards incomplete exports, preserves charged quota; old tasks cannot be resumed into a new Preview context. This is a single-instance process boundary, not distributed quota control.

Beta routes bypass normal HTTP access logging. Credentials/session tokens never enter Preview inputs, results or exports. Export measurements remain `verification=pending`, `lineageClaim=none`. Storage does not import/write Canonical Graph/cache; browser checks canonical cache digest stability.

## Acceptance and future operation

Offline tests exercise default-off, anonymous/invalid auth, exact-origin/CSRF/forwarded headers, duplicate cookies, session rotation/expiry, two-identity result isolation, full real-engine fixed Mock flow, shared quota/login persistence, concurrency/cancellation, actual stricter 10-second provider timeout within the 30-second task ceiling and durable restart. Browser acceptance covers login → Graph → Deep Search → source selection → comparison → evidence/download → Graph at 390/430/1280/1920px. Results are fixed Mock data consumed by the actual engine, not real GitHub benchmark scores.

Before any private deployment: separate approved server/TLS proxy route that satisfies the fixed-origin and rejected-forwarded-header contract, protected credential provisioning/rotation, independently owned mode-0700 store outside production cache/jobs/checkout, operator lock-recovery procedure, durable-volume/backup policy, monitored quota sizing and administrator access review. Normal production must keep this entry absent. Public/multi-user exposure additionally needs authentication review, abuse controls, security review, WebKit/physical-device acceptance and separate release authorization. No deployment is authorized by this document.

Security design references: [OWASP CSRF prevention](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html) and [OWASP session management](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html). Exact origin, custom request headers, no CORS, cookie attributes and session revocation are deliberately combined; SameSite alone is not claimed sufficient.
